# 大模型应用开发实操（垂直领域知识库切片 · LLM 应用分册）

> 用途：面向大模型应用开发岗位技能培训的工程知识底座，供 RAG 检索增强生成使用。
> 覆盖范围：Prompt 工程、RAG 架构、Agent 编排、微调、模型评测与幻觉防控。
> 适用对象：大模型应用工程师、AI 产品工程师、转岗培训学员、企业内训。

---

## 一、Prompt 工程规范

### 1.1 提示词结构四要素
1. 角色设定（Role）：明确身份、专业领域与语气边界，例如"你是资深数据工程师，只输出可执行 SQL"。
2. 任务描述（Task）：动词开头、目标明确、可量化（"抽取以下简历中的公司名与起止时间，输出 JSON"）。
3. 约束条件（Constraints）：输出格式、长度、禁止事项；关键约束放在提示词头部与尾部各重复一次效果更稳。
4. 示例（Few-shot）：3～5 个覆盖边界情况的示例优于大量普通示例；分类任务每个类别至少 1 例。

### 1.2 进阶技巧
- 思维链（CoT）：在复杂推理任务追加"请先逐步分析再给结论"，数学类任务准确率可提升 10%～30%；注意与"直接输出 JSON"的格式约束冲突时，用两段式（先思考后输出）解决。
- 自洽性（Self-Consistency）：同一问题采样 5～10 次投票取多数，代价是成本翻倍。
- 结构化输出：优先用 JSON Schema/函数调用约束而非正则解析自然语言；对不支持函数调用的模型，给出完整 JSON 模板并要求"只返回 JSON，不要解释"。
- 提示词版本管理：提示词视为代码纳入 Git，每次修改记录评测集分数回归。

### 1.3 常见反模式
| 反模式 | 后果 | 修正 |
|---|---|---|
| 指令堆砌无结构 | 模型忽略部分指令 | 分节编号，重要约束加"必须" |
| 示例含敏感/错误内容 | 模型模仿错误 | 示例人工审核 |
| 单提示词塞多任务 | 相互干扰 | 拆分为路由+子任务 |
| 依赖"请务必准确"类空话 | 无实际增益 | 给出验证标准与示例 |

## 二、RAG 检索增强生成

### 2.1 标准架构五阶段
1. 加载（Load）：PDF/Word/HTML/Markdown 解析；扫描件需 OCR；表格建议转 Markdown 保留结构。
2. 切分（Chunk）：固定长度 300～800 token + 10%～15% 重叠；按语义边界（标题/段落）切分优于硬截断；父子块策略（子块检索、父块喂给 LLM）兼顾精度与上下文。
3. 向量化（Embed）：中文主流选择 bge-large-zh / text-embedding-v3 等；同一系统入库与查询必须使用同一 embedding 模型。
4. 存储（Store）：向量数据库选型——Chroma 轻量原型、Milvus 大规模生产、pgvector 复用现有 PostgreSQL。
5. 检索与生成（Retrieve & Generate）：Top-K 召回（K=3～8）→ 重排 → 拼 Prompt → 生成。

### 2.2 检索质量优化
- 混合检索：向量召回 + BM25 关键词召回，RRF（Reciprocal Rank Fusion）融合，对专有名词、型号、编号类 query 显著提优。
- 重排序：bge-reranker 等 Cross-Encoder 对 Top-20 粗排结果精排取 Top-5，是性价比最高的优化点。
- 查询改写：多轮对话中将指代补全（"它的原理是什么"→"ResNet 的原理是什么"）；HyDE 用假设答案增强检索。
- 元数据过滤：为 chunk 打上 domain/doc_type/date 标签，检索时先过滤后相似度计算。

### 2.3 引用溯源规范（高保真要求）
- 生成答案的每条关键结论必须标注来源文档名与块 ID，前端渲染为可点击引用。
- 检索置信度阈值：最高相似度距离超过阈值（如余弦相似度 <0.6）时应回复"知识库中未找到依据"，禁止强行作答。
- 答案-证据一致性校验：可用 NLI 模型或 LLM 二次校验"该结论是否能由引用片段推出"，不通过则触发重生成。

### 2.4 RAG 评测指标
- 检索层：Hit Rate@K、MRR（平均倒数排名）。
- 生成层：忠实度（Faithfulness，答案是否被证据支撑）、答案相关性、上下文精确率。RAGAS 框架可直接产出上述指标。
- 达标参考线：垂直领域问答 Faithfulness ≥0.85、Hit Rate@5 ≥0.9 为可用基线。

## 三、Agent 与多智能体编排

### 3.1 Agent 基本构成
Agent = LLM（决策核） + 记忆（短期对话窗口 + 长期向量库） + 工具集（Function Calling） + 规划策略（ReAct/Plan-and-Execute）。
ReAct 循环：Thought（推理）→ Action（调用工具）→ Observation（观察结果）→ 循环直至 Final Answer。

### 3.2 多智能体协作模式
- Supervisor 模式：主控 Agent 负责任务分解与路由，专家 Agent 只负责单一职责，结果由主控聚合——可控性最强，适合生产环境。
- 辩论/交叉验证模式：多个 Agent 独立作答后互评、裁判裁决，用于消除幻觉、提升事实准确性；典型配置 2～3 个辩手 + 1 个裁判。
- 流水线模式：A 的输出作为 B 的输入（如 大纲 Agent→写作 Agent→审校 Agent），依赖关系清晰。
- 选型原则：任务可拆且步骤固定选流水线；需要动态决策选 Supervisor；对准确性要求极高叠加辩论层。

### 3.3 生产化要点
- 每个 Agent 必须有独立的 system prompt、温度（生成类 0.7，抽取/判定类 0～0.3）与超时。
- 工具调用必须设置最大循环轮次（如 ≤10）防止死循环；工具异常要返回结构化错误而非让 LLM 幻觉补全。
- 全链路可观测：记录每次调用的 trace_id、prompt 版本、token 用量、耗时；LangSmith/Langfuse 可视化。
- 成本控制：缓存相同请求前缀；小模型路由简单意图、大模型处理复杂任务，可降本 50% 以上。

## 四、微调与模型定制

### 4.1 微调路线决策
数据量 <1000 条：优先 Prompt 工程 + Few-shot；
1000～10000 条高质量标注：LoRA/QLoRA 监督微调（SFT）；
>10000 条且有稳定训练团队：考虑继续预训练或全参微调。
原则：能 RAG 解决的不微调，能 LoRA 解决的不全参微调。

### 4.2 LoRA 实操要点
- 原理：冻结原权重 W，训练低秩增量 ΔW=BA，秩 r 常取 8～64，alpha 取 r 的 2 倍，只作用于 attention 的 q/k/v/o 投影。
- QLoRA：4-bit NF4 量化底座 + LoRA，单张 24GB 卡即可微调 13B 模型。
- 数据格式：instruction/input/output 三元组；质量远重于数量，2000 条精标数据常优于 10 万条弱标注。
- 训练参数起点：lr 1e-4～2e-4（cosine 调度）、epochs 3、batch 等效 64、max_len 按样本 P99 设定。

### 4.3 灾难性遗忘与评估
- 混入 5%～10% 通用语料回放可缓解领域微调导致的通用能力退化。
- 微调前后必须跑同一基准：领域测试集 + 通用能力集（如 C-Eval 子集），两者都不能明显回退才允许上线。

## 五、大模型评测与幻觉防控

### 5.1 评测体系
- 自动指标：准确率/F1（分类）、ROUGE/BLEU（摘要，仅参考）、BERTScore；生成质量以 LLM-as-Judge（GPT-4 级模型打分 + 人工抽检校准）为主流。
- 评测集构建：覆盖高频场景 60%、边界场景 30%、对抗场景 10%；规模 ≥200 条才有统计意义。
- 回归评测：每次改 prompt/换模型/升级 RAG 都必须全量跑评测集，分数下降即阻断发布。

### 5.2 幻觉类型与防控手段
| 幻觉类型 | 表现 | 防控手段 |
|---|---|---|
| 事实性幻觉 | 编造公式/文献/参数 | RAG 强制 grounding、要求标注引用、低温度 |
| 逻辑性幻觉 | 推理跳跃/自相矛盾 | CoT、Self-Consistency、裁判复核 |
| 一致性幻觉 | 多模块产出互相矛盾 | 交叉比对校验（跨模态一致性检查） |
| 范围性幻觉 | 超纲作答/答非所问 | 明确拒答策略、范围约束写入 system prompt |

工程组合拳：检索兜底（找不到证据就拒答）→ 生成约束（引用来源）→ 事后校验（NLI/裁判 Agent）→ 兜底降级（转人工）。多层叠加可将垂直领域幻觉率压到 5% 以下。

### 5.3 安全合规
- 内容安全：输入侧敏感词过滤 + 输出侧审核 API 双重把关。
- 注入攻击防护：用户输入与系统指令分隔（明确标记不可信文本）；工具调用白名单。
- 隐私保护：日志脱敏、用户数据留存期限声明、提供删除接口（PIPL/GDPR 要求）。
