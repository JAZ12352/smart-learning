# 多智能体协作系统架构说明

## 概述

智慧乐学采用双层多智能体架构，Java 端负责**教学资源生成**，Python 端负责**智能分析决策**，通过 API 桥接协同工作。

## Agent 协作流程

系统提供两种工作流，按场景自动选用：

### 1. 对话路由工作流（通用问答 / 单 Agent 场景）
```
用户请求 → Supervisor 意图分类 → 路由到单个专业 Agent → 工具调用 → 合成输出
```
适用于组卷、学情分析、画像构建、答疑等单 Agent 即可完成的请求。

### 2. 多智能体深度协同工作流（资源生成场景，核心创新）
针对"个性化学习资源生成"赛题要求，采用 **Supervisor 编排 + 共享态多 Agent 协同 + 质量回审** 的真协同模式（LangGraph StateGraph 实现），Agent 之间存在真实的数据依赖与状态共享，而非简单并行：

```
教学主题 + 学生画像
        │
        ▼
┌─────────────────── Supervisor Agent（任务规划）──────────────────┐
│  输出协作方案：激活的 Agent 列表、执行阶段、依赖关系、难度定位       │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌ Stage 1 ─ MindMap Agent（先行，产出知识结构写入共享态）──────────┐
└──────────────────────────────┬──────────────────────────────────┘
                               ▼  (复用 MindMap 产出)
┌ Stage 2 ─ 并行扇出（ThreadPoolExecutor，3 个 Agent 同时执行）────┐
│   ┌─ Doc Agent ──────┐  ┌─ Reading Agent ─┐  ┌─ Code Agent ───┐ │
│   │ 依据知识结构写文档 │  │ 依据知识结构写阅读│  │ 依据知识结构写代码│ │
│   └──────────────────┘  └─────────────────┘  └────────────────┘ │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼  (复用 Doc 产出，保证跨模态一致)
┌ Stage 3 ─ Quiz Agent（依据 Doc 文档内容出题）────────────────────┐
└──────────────────────────────┬──────────────────────────────────┘
                               ▼  (复用 Doc + MindMap 产出)
┌ Stage 4 ─ Video Agent（依据文档+知识结构生成视频脚本）────────────┐
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌──────────── Quality Review Agent（资源质量多维度评估）───────────┐
│  准确性 / 难度适配 / 完整性 / 跨模态一致性 四维打分                │
│  发现 critical 问题 → 触发重试（最多 1 次，重跑问题 Agent）       │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
              Supervisor Agent 聚合全部资源 + 质量报告 → 最终输出
```

**协同要点（区别于"路由到单 Agent"的伪多智能体）：**
- **共享状态**：每个 Agent 的产出写入共享 `agent_outputs`，下游 Agent 在 prompt 中显式引用上游产出（如 Quiz Agent 的 prompt 包含 Doc Agent 文档全文，确保题目与文档一致）。
- **数据依赖**：MindMap → (Doc/Reading/Code) → Quiz → Video，存在真实 DAG 依赖，而非独立调用。
- **并行扇出**：Stage 2 三个无依赖 Agent 通过线程池真并行执行，缩短端到端时延。
- **质量回审**：Quality Review Agent 对全部资源做多维度评估，发现严重问题自动触发重试，形成"生成—审查—修复"闭环。
- **实时可观测**：每个 Agent 的 start/end、真实耗时、输入输出摘要通过 SSE 实时推送前端，协作过程完全透明（见 Agent 协作可视化页面）。

## Java 端 Agent 详解

### Doc Agent（课程文档）
- **职责：** 生成结构化教学文档
- **输出：** Markdown 格式，10 章结构（概念→历史→原理→特征→分类→公式→应用→误区→前沿→关联）

### MindMap Agent（思维导图）
- **职责：** 知识体系可视化
- **输出：** 缩进列表格式，8 大维度 × 3+ 子节点，每节点 15-60 字

### Quiz Agent（练习题目）
- **职责：** 多题型评估设计
- **输出：** 选择题3道 + 判断题2道 + 填空题2道 + 简答题1道，含答案和解析

### Reading Agent（拓展阅读）
- **职责：** 前沿文献延伸材料
- **输出：** 7 章：学科背景→前沿动态→跨学科→文献导读→名家观点→争议→思考

### Video Agent（教学视频）
- **职责：** 分镜头教学脚本
- **输出：** 5 个场景（开场→概念→原理→实例→总结），每个含画面文字+语音讲解

### Code Agent（代码案例）
- **职责：** 可运行教学代码
- **输出：** 3 个难度递进示例，含注释、运行方式、预期输出

## Python 端 Agent 详解

### 对话路由 Agent（通用问答场景）

| Agent | 职责 | 依赖 |
|-------|------|------|
| **Supervisor** | 意图分类、任务路由、结果合成 | LLM |
| **Paper Agent** | 智能组卷（知识点覆盖、难度分布） | MySQL |
| **Question Agent** | 练习题推荐（薄弱点、错题分析） | MySQL + ChromaDB |
| **Student Agent** | 学情分析（成绩趋势、优劣势） | MySQL |
| **Profile Agent** | 8 维度学生画像构建 | MySQL |
| **Resource Agent** | 多模态资源编排 | Java API |
| **Path Agent** | 个性化学习路径规划 | MySQL |
| **QA Agent** | 智能辅导/答疑 | MySQL + ChromaDB |
| **Teaching Agent** | 教案设计、PPT 大纲 | ChromaDB |

### 深度协同 Agent（资源生成场景，共享态协作）

| Agent | 职责 | 上游依赖（共享态输入） |
|-------|------|------------------------|
| **Supervisor** | 任务规划：确定激活 Agent、阶段、依赖、难度 | 教学主题 + 学生画像 |
| **MindMap Agent** | 知识体系可视化（8 维 × 3+ 子节点） | — |
| **Doc Agent** | 课程讲解文档（10 章 Markdown） | MindMap 产出 |
| **Reading Agent** | 学术前沿拓展阅读（7 章） | MindMap 产出 |
| **Code Agent** | 可运行教学代码（3 难度递进） | MindMap 产出 |
| **Quiz Agent** | 练习题目（4 题型，含答案解析） | Doc 产出（保证题文一致） |
| **Video Agent** | 教学视频脚本（5 场景画面+语音） | Doc + MindMap 产出 |
| **Quality Review Agent** | 资源质量四维评估 + 问题定位 + 重试决策 | 全部 Agent 产出 |

## 技术栈

| 层级 | 技术 |
|------|------|
| 编排框架 | LangGraph (Python) / 原生串行编排 (Java) |
| LLM 后端 | DeepSeek / OpenAI 兼容 |
| 向量检索 | ChromaDB |
| 数据库 | MySQL 8.0 |
| 通信协议 | REST API + SSE 流式传输 |
| 后端框架 | Spring Boot 2.1.6 / FastAPI |
